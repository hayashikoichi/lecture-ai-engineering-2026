# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 素のLLMはこの講座の知識がないため一般知識を用いて回答を生成していた。そのため、「第n回のこのキーワードが...」というタスクについては、それっぽい回答をするか知らないと答えるにとどまった
  - 今回作成したエージェントは、toolsによって用語集をロードしたり、それに基づいてクイズを作成したりした。toolsで呼び出せる知識を元に回答や実装を生成できる。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - [tool call]   make_quiz({'lecture': 2})
  
    [tool return] make_quiz -&gt; {"question": "「エポック」の意味は？", "answer": "学習データ全体を1周学習することを1エポックと数える。回数を増やしすぎると過学習しやすい。"}…
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 2
- 追加したツールと、docstring に書いた説明：
  ```python
  指定した回の用語から 1つを選び、確認問題と答えを返す。
  
      「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。
  ```

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - make_quizというtoolのdocstringに、以下の文言を追加した。
    ```python
        複数回の講義回が指定されたときは、それぞれの講義回についてmake_quizを行う。
    ```
- 結果：
  - uv run python -m app.agent --trace "第2回と第4回の内容から 確認問題を1問出して" というコマンドで比較。
  - 編集前は、第2回の講義内容についてのみクイズを生成し、第4回については何も出力がなかった。
  - 編集後は、プロンプトにて言及した回についてのクイズを生成した。
- 気づき・疑問：
  - 単一の講義回を指定した際は、問題とヒントの組み合わせを出力していたものの、複数講義回を指定すると**問題と答え**の組みが出力された。さらに、おそらく何かしらのCLIツールでのレンダリングを想定しているのか、htmlタグを以下の出力となっていた。
  - 「答えを出力するな」という旨が書かれたINSTRUCTを無視するまでは理解できるが、わざわざhtmlタグを含むようになったのはよくわからない。

```
<details>
<summary>答えを見る</summary>
自動判定では決められない項目（LLMが unsure と答えた項目）を、人が見る列に回すこと。一致率の計算からは外す。要確認が出た項目は、基準に書いていなかったことの印なので、方針を決めて基準に書き足す。
</details>
```
